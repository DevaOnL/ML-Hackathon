# PathSnap execution plan and acceptance contract

## Authoritative scope

The six documents added in `PathSnap_student_materials/` supersede the initial video-only interpretation. The complete guide is a concatenation of the five supporting documents. The video introduces map matching; the written materials require a distributed learned system and two final deliverables: a **public GitHub repository** and **one consolidated PDF report**.

## Ordered work packages

1. **Inspect inputs.** Read all documents including nested tables and embedded images; read the entire video timeline and narration; parse every row of all 360 dataset files; record hashes and anomalies.
2. **Define supervision and splits.** Preserve zero-based original arc IDs. Route labels are sequences, not GPS-aligned classes. Derive clearly documented observation proxy labels using reference geometry only in fitting/scoring. No reference-derived feature or inference input. Use trip-grouped cross-validation over all 80 training trips; the ten student-test trips are permitted development comparisons. Reserved evaluator data is not provided and remains untouched.
3. **Feature engineering.** Exact directed-segment projections, meter-based lateral distance, candidate rank, edge geometry/topology, and GPS-only local motion/heading/time features. Candidate generation has independent miss-rate measurement. Fit learned preprocessing inside each training fold.
4. **Five-model experiment.** Train at least five distinct probabilistic classifiers using identical trip folds and candidate data. Record parameters, fold memberships, seeds, training/inference times, accuracy, precision, recall, binary macro F1, log loss, top-1 observation proxy accuracy, candidate miss rate and classifier continuity. Retain real per-fold and student-development results.
5. **Bayesian optimisation.** Select a promising family from recorded grouped-CV evidence; perform a genuinely model-based search (Gaussian-process expected improvement), record every trial/search range/objective, refit using training data only, and compare tuned/untuned on the same folds/student trips.
6. **Route reconstruction.** Use final classifier probabilities in directed-edge HMM emissions with a geometric residual term. Use shortest-path/chord transition costs, log-space Viterbi and full arc reconstruction. Preserve loops, one-way edges and missing intermediate arcs. Expose failures; never fabricate an edge or teleport. Estimate/validate decoder configuration on permitted data and save it. Compare classifier-only versus HMM pointwise proxy metrics, route continuity and repeated-arc/sequence overlap.
7. **Laptop 1 service.** FastAPI dynamically discovers all ten configured trip IDs, loads the trained artifact and decoder config, performs fresh inference on requests, then scores private references server-side. Validate IDs, sanitize errors, log requests/model hashes/timings. No reference labels or geometry in API responses.
8. **Laptop 2 interface.** Independently served responsive UI, configurable LAN API URL, all-trip selector, live POST, route/GPS map, measured scores and latencies, empty/loading/error states. Geometry works offline without map tiles; no hardcoded answers or bypass.
9. **Evidence and report.** Actual EDA/missing-value plots, model/CV/student/optimisation charts, per-model discussion and compulsory questions, Folium layers (GPS/network/reference/prediction) for development only, real map/UI/API-log screenshots, one consolidated PDF. Clearly state proxy-label uncertainty and absence of a physical two-laptop or hidden-evaluator demonstration in this environment.
10. **Verification and publication.** Independent synthetic tests, reference-access guards, grouped split audits, model artifact roundtrip, all-ten live API exercise, UI browser smoke, repeatability and source/report review. Publish coherent component commits and pull requests using the four requested authenticated accounts; do not backdate history or claim account attribution proves human authorship.

## Ownership and coordination

- Lead: input consolidation, graph/routing/matcher/metrics/CLI, integration, report, repository operations.
- Learning teammate: feature extraction, supervised experiments, Bayesian optimisation and small trained artifacts.
- Service teammate: backend and two-laptop deployment scripts.
- Interface teammate: standalone evaluator UI and vendored map assets.
- Verification teammate: tests and independent review only.
- Focused analysis sub-agents: data integrity, video transcription, algorithm baseline and instruction completeness.

Write scopes are disjoint on the shared task board; the Lead reviews final changes and runs the integrated checks. Raw inputs and credentials are not redistributed. All reported results must be generated by submitted code; no artificial curves, citations, screenshots or final-evaluator scores.

## User-approved public deployment

The user subsequently replaced the separate-laptop requirement with a real website at **https://ml.d3va.dev**, hosted from this computer through Cloudflare. Serve the UI and API from one origin, bind the local API to loopback, keep reference data server-private, and run the API/tunnel as isolated restartable user services. No credentials are stored in Git. A successful local run is not proof of public hosting: verify DNS, HTTPS, UI, API and a real inference request at the exact hostname before claiming it is live.

## Known external boundary

The ten reserved evaluator trips are absent. The implementation must support an evaluator root without code changes. Cloudflare zone/tunnel authentication must be available to create the requested hostname safely; if it is missing, document that concrete blocker and complete the local system while waiting. Never overwrite unrelated DNS records or stop existing websites.
